# Запуск и публикация

## Что уже проверено

Приложение запущено через Uvicorn и проверено в Chromium: регистрация двух аккаунтов, создание задачи, отклик, решение и подтверждение прогресса. Данные переживают перезагрузку страницы.

**Постоянная публичная ссылка ещё не создана.** В исходной рабочей среде отключены сервисы публикации, нет учётных данных хостинга и API-ключа. Конфигурация ниже подготовлена для агента, которому доступен ваш GitHub и выбранный хостинг. Нельзя выдавать локальный адрес за публичную ссылку.

## Быстро открыть внешний вид

Откройте `TaskReady-demo.html`. Это автономный локальный режим с учебными данными и переключением демо-ролей. Он не создаёт реальные аккаунты и не вызывает LLM. Полноценная серверная версия доступна после запуска Python или Docker.

## Сервер на компьютере

Windows: `powershell -ExecutionPolicy Bypass -File scripts/run.ps1`.
Linux/macOS: `sh scripts/run.sh`.

Откройте http://127.0.0.1:8000. Создайте аккаунт бизнеса. В другом профиле браузера зарегистрируйте команду. На новом сервере нет скрытых предустановленных пользователей и паролей.

Чтобы использовать LLM, установите `TASKREADY_AI_API_KEY` в окружении процесса **на сервере**. Файл `.env` автоматически используется Docker Compose; Python-скрипт запуска не читает его. В Python-режиме используйте переменные окружения терминала или секреты платформы.

## Docker

1. Скопировать `.env.example` в `.env` и при необходимости заполнить ключ.
2. Выполнить `docker compose up --build -d`.
3. Открыть http://127.0.0.1:8000.

Compose использует именованный volume `taskready-data`. Контейнер работает от отдельного непривилегированного пользователя. Docker Engine в среде разработки не был доступен, поэтому образ не собирался здесь; проверен Python-запуск того же приложения.

## Публичное демо на Render

В проекте есть `render.yaml` по формату [Render Blueprints](https://render.com/docs/blueprint-spec).

1. Перенести содержимое `taskready-ai/` в корень существующего репозитория организаторов.
2. Проверить права аккаунта на этот приватный репозиторий и разрешить доступ хостингу, если организация это допускает.
3. На Render создать Blueprint из репозитория. Конфигурация использует платный `starter` и постоянный диск; владелец хостинга должен проверить стоимость до создания сервиса.
4. Добавить `TASKREADY_AI_API_KEY` через поле секрета платформы. Без ключа можно выбрать локальную проверку.
5. После запуска сохранить полученный HTTPS URL. При желании задать `TASKREADY_PUBLIC_ORIGIN` равным этому origin без завершающего `/`.
6. Проверить `/api/health`: `status=ok`. `aiConfigured=true` означает наличие конфигурации, а не проверку баланса или валидности ключа.
7. Создать два аккаунта и пройти сценарий из `DEMO_SCRIPT.md`, включая реальный вызов AI.
8. Перезапустить сервис и убедиться, что задачи сохранились на диске.

## Самостоятельный сервер

Поставить HTTPS reverse proxy перед портом 8000; использовать `APP_ENV=production`, `TASKREADY_PUBLIC_ORIGIN=https://ваш-домен`. В production cookie имеет флаг Secure. Нельзя проверять такую конфигурацию через обычный HTTP: браузер не отправит cookie.

Один процесс и одна постоянная SQLite-база подходят для небольшого пилота. Не запускать независимые экземпляры с отдельными базами. Для масштабирования перенести данные в PostgreSQL.

## Резервирование

`python scripts/backup.py /безопасный/путь/backup-2026-09-23.sqlite3`.
Скрипт делает согласованную копию средствами SQLite. База и резервные копии содержат пользовательские данные и не включаются в Git/ZIP.

## Ограничения пилота

Нет восстановления пароля по email, подтверждения email, MFA, приглашений в многопользовательскую команду и админ-панели. Один аккаунт команды представляет одну команду. Роль выбирается при регистрации, изменить её через браузерный переключатель на сервере нельзя. Публикации доступны зарегистрированным пользователям; публикация карточки является явным подтверждением владельца.
