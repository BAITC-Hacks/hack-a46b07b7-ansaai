# TaskReady AI · 0.3.0

Подготовка бизнес-задач для студенческих команд: описание → вопросы → подтверждённая карточка → каталог → отклик → ручной выбор → подтверждённый результат.

## Открыть демо

**`TaskReady-demo.html`** — один автономный файл, открыть в браузере. Работает без ключа и интернета на учебных данных. Изменения хранятся локально. Аккаунты и внешняя модель доступны в серверной версии.

## Запустить сервер

Python 3.12+:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install -r backend/requirements.txt
python scripts/build_demo.py
uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Открыть http://127.0.0.1:8000. Зарегистрировать бизнес и команду в отдельных профилях браузера. Есть скрипты `scripts/run.sh` и `scripts/run.ps1`, а также Docker Compose.

## Что изменилось

- Отдельные аккаунты с проверкой прав на сервере, CSRF, хешированием паролей, HttpOnly cookie.
- Задачи имеют владельца и версию; повторная отправка не дублирует публикацию.
- Отклики уникальны для пары команда/задача. Окончательное решение нельзя многократно переключать. Бизнес может выбрать несколько команд.
- +5 за выбор команды и +10 за один подтверждённый этап. Начисление атомарно и идемпотентно.
- Семь критериев конкретности с объяснением каждого балла. Формула больше не опирается на длину текста.
- OpenAI Responses API со структурированным выводом и проверкой цитат. AI не публикует карточку сам.
- Сохранён согласованный дизайн: светлый зелёный, плотные шрифты, поиск, фильтры и адаптивная вёрстка.

## Подключить LLM

Установить в серверном окружении `TASKREADY_AI_API_KEY` (или `OPENAI_API_KEY`) и `TASKREADY_AI_MODEL` (по умолчанию `gpt-4.1-mini`). Для Docker Compose скопировать `.env.example` в `.env`. Никаких ключей во frontend.

Если ключ не настроен, интерфейс честно предлагает локальную проверку. Если провайдер отвечает с ошибкой, ошибка показывается; автоматической подмены ответа «AI» локальными правилами нет.

Живой API-вызов **не проверен в исходной среде**: ключ отсутствует. Контракт, валидация и обработка ошибок проверяются тестами. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

## Проверки

```bash
pip install -r requirements-dev.txt
python scripts/build_demo.py
node --check app.js
python -m pytest -q
python scripts/evaluate_ai.py
# С ключом, вызывает внешний платный API:
python scripts/evaluate_ai.py --live
```

`tests/e2e.cjs` проверяет серверный сценарий в двух независимых браузерных контекстах. Инструкции: `docs/HANDOFF.md`.

## Структура

- `backend/main.py`: API, аккаунты, сессии, SQLite, права, публикации и отклики.
- `backend/ai.py`: реальная интеграция модели и явный локальный режим.
- `backend/scoring.py`, `public/rubric.json`: общая прозрачная рубрика.
- `app.js`, `styles.css`, `index.html`: исходники интерфейса.
- `public/`: генерируемые frontend-файлы, единственные публично доступные ресурсы.
- `scripts/build_demo.py`: сборка public и HTML-демо.
- `docs/HANDOFF.md`: инструкции агенту для переноса в репозиторий и публикации.
- `docs/DEPLOYMENT.md`: конфигурация хостинга, ограничения и backup.
- `docs/PITCH.md`, `docs/DEMO_SCRIPT.md`: защита и сценарий.

## Честный статус

Серверные тесты и браузерный сценарий пройдены. Публичный URL не создан; ключ внешней модели не подключён. Docker-конфигурация подготовлена, но образ не собирался: Docker Engine отсутствовал. Render-конфигурация использует платный инстанс с постоянным диском.

Продукт предназначен для хакатонного пилота. В нём ещё нет восстановления пароля, email-верификации, состава команды из нескольких аккаунтов и масштабирования БД. Рубрика проверяет конкретность, не доказывает достоверность и реализуемость задачи. Новая база не перезаписывает старый общий демо-state; импорт старых данных требует сопоставления владельцев.
